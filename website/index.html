Why invo

Small, opinionated, local-first.

Four decisions that make this different from sending your receipts to a web form or wiring up a Zapier chain.

01 / LOCAL BY DEFAULT

Your PDFs never leave your machine.

Ollama is the default provider. A 1.5B model on your laptop is good enough for structured extraction from a clean receipt. No tokens billed, no accounts, no upload.

ollama qwen2.5:1.5b
02 / EXPLICIT PROVIDERS

Choose the configured provider for a run.

invo uses the first enabled provider by default. Add an OpenAI provider entry with api_key_env, then select it with --provider openai when local extraction is not enough.

ollama openai
03 / STRUCTURED, TYPED

A JSON schema, not a blob of text.

20+ fields — vendor, dates, ISO-4217 currency, tax breakdown, line items with quantity and unit price, buyer identity match, confidence. Numbers are numbers. Dates are YYYY-MM-DD.

json yaml csv
04 / PIPELINE INPUT

Globs, stdin, and file lists.

Hand it "receipts/**/*.pdf", pipe one PDF with invo -, or pass newline-delimited paths with --files-from. Batch JSON is compact NDJSON unless you ask for one array.

glob stdin ndjson
Quick-start

Four shapes of the same command.

A single binary. One positional argument, stdin, a file list, or a glob. Everything else has a default. 

$ invo init
# Created config file at ~/.config/invo/config.yaml

$ invo receipt.pdf --json
# → compact structured JSON on stdout; diagnostics stay on stderr
$ invo "receipts/2025/**/*.pdf" --json > receipts.ndjson
# Expands the glob and emits one compact JSON object per line.

$ printf '%s\n' receipts/jan.pdf receipts/feb.pdf > receipts.txt
$ invo --files-from receipts.txt --json-array > receipts.json
# Use a file list when another script already selected the PDFs.
$ invo receipt.pdf --format yaml
# Human-readable YAML instead of JSON

$ invo - < receipt.pdf
# Read PDF bytes from stdin; file metadata is stdin.pdf

$ invo receipt.pdf --format csv
# Header + row: vendor,date,total,currency,invoice_number
# Pipe-friendly for spreadsheets, ledgers, or hledger imports.
$ export OPENAI_API_KEY=sk-...
$ invo receipt.pdf --provider openai -vv
# Selects the configured OpenAI provider for this run.

$ invo config validate -c config.yaml --json
# Validate config before switching providers in scripts.
Configuration

One YAML, teach it your vendors.

Known vendors improve extraction accuracy, and identity context tells the model which names belong to you, the buyer. The starter file is config.yaml.

~/.config/invo/config.yaml 
identity:
  company: "Liseth Solutions AS"
  email: "helge@example.com"
  vat_number: "NO123456789MVA"

llm:
  providers:
    - name: ollama
      enabled: true
      model: "qwen2.5:1.5b"
      base_url: "http://localhost:11434"
    - name: openai
      enabled: false
      model: "gpt-4o-mini"
      api_key_env: "OPENAI_API_KEY"
  extraction:
    temperature: 0.1
    max_tokens: 2000
    retry_attempts: 2

vendors:
  - name: "Google Workspace"
    patterns: ["Google Ireland Limited", "google.com/pay"]
    currency: "EUR"
    category: "software"
    hints: "Google receipts often use Google Ireland Limited as the legal vendor."

output:
  format: json
