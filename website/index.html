Why invo

Small, opinionated, local-first.

Four decisions that make this different from sending your receipts to a web form or wiring up a Zapier chain.

01 / LOCAL BY DEFAULT

Your PDFs never leave your machine.

Ollama is the default provider. A 1.5B model on your laptop is good enough for structured extraction from a clean receipt. No tokens billed, no accounts, no upload.

ollama qwen2.5:1.5b
02 / PROVIDER CHAIN

Fall back when local isn't enough.

Set OPENAI_API_KEY or ANTHROPIC_API_KEY and invo tries Ollama first, then the others in config order. Per-run override via --provider when you know better.

openai anthropic
03 / STRUCTURED, TYPED

A JSON schema, not a blob of text.

20+ fields — vendor, dates, ISO-4217 currency, tax breakdown, line items with quantity and unit price, buyer identity match, confidence. Numbers are numbers. Dates are YYYY-MM-DD.

json yaml csv
04 / BATCH & FILE

Glob, parallelize, rename, archive.

Hand it "receipts/**/*.pdf" and it processes in parallel via rayon. Post-extraction actions rename and file the PDF into {year}/{month}/{vendor}_{total}.pdf. Deduped by SHA-256.

glob rayon sha-256
Quick-start

Four shapes of the same command.

A single binary. One positional argument or a glob. Everything else has a default. 

$ invo init
# Created config file at ~/.config/invo/config.yaml

$ invo receipt.pdf
# Processing 1 file(s) · ollama (qwen2.5:1.5b) · 1.4s
# → prints structured JSON to stdout
$ invo "receipts/2025/**/*.pdf"
# Expands glob, processes each PDF in parallel via rayon.
# Per-file JSON to stdout; duplicates skipped via SHA-256.

$ invo "receipts/2025/**/*.pdf" | jq '.invoice.total_amount' | awk '{s+=$1} END {print s}'
# Sum totals across a year of receipts. No spreadsheet.
$ invo receipt.pdf --format yaml
# Human-readable YAML instead of JSON

$ invo receipt.pdf --format csv
# Header + row: vendor,date,total,currency,invoice_number
# Pipe-friendly for spreadsheets, ledgers, or hledger imports.
$ invo receipt.pdf --provider anthropic
# Skip the fallback chain — force Claude for this run.

$ invo receipt.pdf --provider openai -vv
# Trace logs: prompt, raw response, parsed schema, timing.
Configuration

One YAML, teach it your vendors.

Known vendors improve extraction accuracy and let invo apply per-vendor defaults (currency, category). Post-extraction actions file the PDF into a tidy tree.

~/.config/invo/config.yaml 
llm:
  providers:
    - name: ollama
      model: "qwen2.5:1.5b"
      enabled: true
    - name: anthropic
      model: "claude-sonnet-4"
      api_key_env: "ANTHROPIC_API_KEY"
      enabled: true

vendors:
  - name: "Google Workspace"
    patterns: ["Google Ireland Limited", "google.com/pay"]
    currency: "EUR"
    category: "software"

actions:
  - type: copy
    destination: "~/Documents/Receipts/{{year}}/{{month}}/"
    filename: "{{date}}_{{vendor_slug}}_{{total}}.pdf"
    create_dirs: true
